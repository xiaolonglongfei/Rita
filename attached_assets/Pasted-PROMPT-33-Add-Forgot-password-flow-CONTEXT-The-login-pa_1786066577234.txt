PROMPT #33 — Add "Forgot password" flow

CONTEXT:
The login page currently has no way for a user to recover their account if 
they forget their password. There is no "Forgot password?" link and no 
associated flow.

TASK:

1. Add a "Forgot password?" link on the login page, positioned near the 
   password field (standard placement — e.g. below the password input, 
   above or near the Log In button).

2. Clicking it navigates to a simple "Reset your password" page: user enters 
   their email, submits.

3. Wire this to Supabase Auth's built-in password reset:
   supabase.auth.resetPasswordForEmail(email, { redirectTo: '<your-app-url>/reset-password' })

4. Build the /reset-password page that Supabase redirects the user to after 
   they click the link in their reset email — this page should let them set 
   a new password (using supabase.auth.updateUser({ password: newPassword })).

5. IMPORTANT — email deliverability/branding consistency: by default, 
   Supabase Auth sends this email through Supabase's own infrastructure, not 
   through Resend. Since all other transactional emails (welcome, session 
   verification, confirmation) already go through Resend on the verified 
   support.rovi.training domain, configure Supabase Auth's SMTP settings to 
   route through Resend as well, so the password reset email matches the 
   sender domain and branding of every other email the user receives from 
   Rovi. (Supabase Dashboard → Authentication → Email Templates / SMTP 
   Settings — this may require inputting Resend's SMTP credentials there.)

6. Regardless of whether the entered email exists in the system, show the 
   same generic confirmation message ("If an account exists for this email, 
   a reset link has been sent") — do not reveal whether an email is 
   registered, to avoid leaking which emails have accounts.

DONE WHEN:
[ ] "Forgot password?" link visible and tappable on both desktop and mobile 
    login pages
[ ] Submitting a valid registered email triggers a reset email from 
    noreply@support.rovi.training (not a generic Supabase address)
[ ] Clicking the link in that email successfully lands on a working 
    reset-password page
[ ] Setting a new password there allows immediate login with the new password
[ ] Submitting a non-existent email shows the same generic message as a 
    valid one (no account enumeration)
